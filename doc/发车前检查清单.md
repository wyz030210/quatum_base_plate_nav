## 1. 硬件与遥控器 ⚠️ 最容易出事的一节

> 依据：`vehicle_can_bridge/docs/DEPLOYMENT.md:273-274`

- [ ] **物理急停在手边**，且已确认可用（按下去车会断电/断使能）
- [ ] **RC 遥控器模式切换通道处于已知挡位** —— 你必须**确定**它现在在哪个挡
- [ ] **RC 摇杆在中位**
- [ ] **有人持握遥控器**，全程不松手

> ### 为什么这几条是硬性的
>
> - **控制权是静默移交的**：STM32 一旦在组合控制 CAN 通道（`0x06`）上收到**任意一条**消息，
>   如果此时 RC 模式通道在"自动"位置，就会从手动切到自动（ROS 指令）控制 ——
>   **哪怕发的是一条零速指令**。也就是说 `cmd_vel_to_can` 一启动，车就已经交给 ROS 了。
> - **500 ms 超时会把控制权交回 RC**：ROS 侧停止发送超过 500 ms，STM32 自动退回 RC 手动。
>   这是唯一的硬件兜底，但它意味着 —— **触发时若摇杆不在中位，车会按摇杆当前位置动作**。
> - 两个方向都要防：启动时 RC 在自动挡 → 静默交给 ROS；看门狗触发 → 交回 RC 且可能突然动。

## 3. 安全层自检 ⚠️ 上新场地前必须实测

```bash
# 3.1 覆盖链是否起来了
ros2 action list | grep execute_coverage_navpath
ros2 topic info /clicked_point                      # 应有订阅者

# 3.2 遥控抢占信号在线（安全层的【前提】）
ros2 topic hz /vehicle/remote_manual_override        # 期望 ≈ 1 Hz

# 3.3 安全层的接线
ros2 node info /coverage_navpath_bridge | grep -A8 Subscribers
ros2 node info /coverage_navpath_bridge | grep -A8 Publishers
ros2 topic list | grep coverage/emergency_stop
```

- [ ] `execute_coverage_navpath` 在
- [ ] `/clicked_point` 有订阅者
- [ ] `/vehicle/remote_manual_override` **≈ 1 Hz** ← **这条不过就不要继续**（CAN 链路有问题时它会消失，软件安全层随之失效）
- [ ] 桥接节点的 Subscribers 里有 `/vehicle/remote_manual_override` 和 `/coverage/emergency_stop`
- [ ] 桥接节点的 Publishers 里有 `/cmd_vel`

**启动日志里应能看到这两行**：

```
coverage_navpath_bridge ready: execute=/execute_coverage_navpath, ...
safety: manual_override=/vehicle/remote_manual_override, emergency_stop=/coverage/emergency_stop, zero_vel_on=/cmd_vel
```

### 3.4 实触发一次（**不要跳过**）

- [ ] 跑一个小区域让覆盖任务动起来 → **拨动遥控器** → 桥接节点日志出现
      `SAFETY ABORT: remote manual override` → **车立即停下**
- [ ] 再跑一次 → 执行
      ```bash
      ros2 topic pub --once /coverage/emergency_stop std_msgs/msg/Bool "{data: true}"
      ```
      → 日志出现 `SAFETY ABORT: software emergency stop` → **车立即停下**

> 两条都应返回 `error_code = 909`。实测响应延迟 13~50 ms。

## 6. 选点与首次试跑

- [ ] **在 RViz 里用 Publish Point 点选多边形**；点回起点附近（阈值 0.35 m）即闭合
- [ ] ⚠️ **选点时以地图上明确的墙体为界**，不要依赖"空白=可走"（地图 `free_thresh: 0.25` 会把未建图区域显示为自由）
- [ ] **第一次只点 3×3 m 左右的小区域**
- [ ] 观察：车是否按路径走、是否撞、是否卡、掉头是否在区域内地头里完成

**通过后再放大**：3×3 m → 单房间 → 全场

- [ ] 全场覆盖预计 **约 15~16 分钟**（252 m² 场地）
      —— ⚠️ **不要直接读 coverage_server 报告的 `task_time`**，那是按 F2C 默认的 **1.0 m/s** 算的。
      换算：`真实耗时 = task_time ÷ 车上实际速度`。
      本车 `max_forward_speed = 0.4`，故 `371 ÷ 0.4 ≈ 928 s ≈ 15.5 min`
      （若临时把速度调回 0.25，则约 24.7 min）

## 8. 异常处理速查

| 现象 | 立即动作 |
|---|---|
| 车要撞 / 跑偏 / 任何不对 | **按物理急停**（最可靠） |
| 想让覆盖任务停下但不想断电 | `ros2 topic pub --once /coverage/emergency_stop std_msgs/msg/Bool "{data: true}"` |
| 自己要用遥控器开 | 直接拨遥控器 → 任务会自动中止；**之后不要拨回"自动"挡**，除非确定要让覆盖继续 |
| 车不动，但任务显示在执行 | 查 `/vehicle/remote_manual_override` 是否为 `true`（遥控器接管中，ROS 指令被忽略）；查 `/vehicle/enabled` |
| 日志出现 `SAFETY ABORT` | 说明抢占或急停被触发，车已收到零速；确认现场情况再重新开始 |
| 覆盖跑到一半停了 | 看桥接节点日志的错误码：`904`=超时、`909`=安全中止、`901`=action server 不可用 |
| CAN 链路疑似掉线 | 除日志外**没有任何告警**（静默降级）。查 `/can_bridge_status`，或看 `/vehicle/remote_manual_override` 是否还有 1 Hz |

> ⚠️ **本项目不记录实际轨迹**。出现"看起来扫完了但角落没扫到"时**没有任何数据可定位漏扫段**，
> 只能整片重跑。所以发现不对要尽早停。
